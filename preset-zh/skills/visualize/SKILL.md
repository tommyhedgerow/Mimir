# 可视化

一张图只有在它显示出文字显示不出的东西时才挣得它的位置：形状、结构、方向、比例、位置。这个技能产出这样一张图，做得正确，并把它放在能渲染的地方。

你是**创意总监**。你决定那一个想法，并把它削减到最少的承载元素。`subagent_diagram_maker` 负责制作并归档结果；你负责放置。

## 一张图什么时候挣得它的位置——以及什么时候不

在想法是下面这些时去伸手：

- **一种结构或关系**——什么依赖什么、什么包含什么、什么供给什么、什么先于什么、什么是什么的另一个版本。
- **一个循环或一个系统**——反馈、稳态、养分循环、岩石循环、一年的季节循环。
- **一套分类或一棵树**——支系、语系、体裁、思想流派、检索表。
- **时间上的一个序列**——时间线、地层、演替、因果链。
- **比例上的比较**——相对尺度、速率、持续时间（没有一张图，深时和地质速率几乎不可能被感觉到）。
- **空间的或地理的**——东西在哪里、一条海岸线或一条山脉或一个流域怎样分割、什么在什么之上或之下。
- **一个论证的骨架**——前提、承重的推理、结论、那个薄弱接点。

当散文或一句话已经承载了它时，**不要**可视化。一张重述旁边那句话的装饰性图，增加了噪声，也增加了一次出错的机会。拿不准时就不要：缺一张图比多一张假图便宜。

**同样的检验也适用于学习者自己的数据，而且它更容易失手。** 现在库里记录了下限、边缘、提取和探测分数，就有一种固定的诱惑去把这些画成图表。不要。一张按学科统计概念数的柱状图是装饰；一条穿过单个数据点画出来的留存曲线比没有曲线更糟。问这张图会改变哪个决定——如果答案是“没有”，那张表格已经说完了。

**依赖图是那条证明规则的例外。** 在这套方法里，课程*就是*一张依赖图，所以几乎每次会话都想要一张已批准计划的小 mermaid DAG——那是一张承载教学法本身的图，不是装饰。

## 选媒介

三种，哪一种都不需要装任何东西：

- **mermaid，在一条 markdown 笔记里**——用于一个*只画一次*的关系性想法，在会话笔记里：一个流、一个序列、一个状态机、一棵树、一条时间线。Obsidian 原生渲染 ```mermaid``` 块，所以它住在笔记里，可以当作文字编辑。**它不再是线索图谱的默认做法**——那些是生成的 SVG（见下），因为 mermaid 的样子差，而它的默认设置让图大到塞不进那一栏。
- **SVG，作为 `Viz/` 里的一个文件**——用于任何精确位置、比例或形状本身就是内容的东西：地图和剖面、带分支长度的支序图、解剖布局、地质柱、几何图形。Obsidian 在阅读视图里渲染嵌入的 SVG。**线索依赖图就是这样画的**，由 `Tools/vault-chart.mjs` 生成——见*图上的状态*。
- **一个实时视图，在一个 `.base` 文件里**——用于任何*从笔记里读出来*而不是画出来的东西：什么到期了、什么不稳固、每条线索站在哪里、探测进行得怎样。`Learn/概览.base` 装着它们，`Learn/概览.md` 嵌入它们。base 不是图；它是一条查询，在它下面的笔记移动时仍然为真。每当答案每周都在变、而重画的图到周二就过期时，就用它。

经验法则：**节点和边 → mermaid。位置和形状 → SVG。任何对他们的状态做的查询 → base。**

**学科的图，和他们的图。** 依赖图是*学科*的图。base 视图是*他们*的图。把两者分开——而它们合理地相遇的唯一地方，是一张框的颜色由他们实际提取到什么决定的图，那图是生成的，从不手画（见*图上的状态*）。

如果它是一张真实地方的地图，用 mermaid 之前要想清楚；一张示意性的海岸线通常是谎言，而框线图不是。

### 一张图得塞进那一栏

学习者在 Obsidian 里读，而且是**滚动而不是平移**，所以一张从左到右的图会跑出面板的侧面。把所有东西都改成竖的解决了这一点，却造出一个更糟的问题：mermaid 默认内边距下的 `graph TD`，让一张五个层级的图有整屏那么高，于是他们每次去核对计划都得*绕着*它滚。**在库里上过一节课之后修订：mermaid 可视化很难看，而且对页边来说太大，这只会增加摩擦。** 所以规则不是“竖着”。是**“塞得下”**。

- **一眼看完，不用滚。** 目标是高度在 ~400px 以下，并且在阅读栏之内（开着 `readableLineLength` 时约 720px，而他们是开着的）。如果需要滚动，它就太大，而修法是**更少的节点或换一种形式，绝不是更小的字号**。
- **标签是一行短句，或者两行——绝不是一整段注解。** 解释属于图旁边那份散文清单，而它本来就在那里；一个重复相邻句子的标签，白白让每个框都翻倍。
- **竖着仍然在任何画图的地方成立**——它按被讲授的顺序被读到——但高不再是没有代价的。
- **一条链不是一张图。** 如果每个节点恰好只有一个后继，那张图就是画成框的清单——去画那份清单。只有分叉、汇聚和交叉链接才挣得一张 DAG。神话图谱那个九节点链是不该画什么的实例。
- **在给绘图员的每一份简报里说明方向和尺寸上限。** 绘图员看不见自己的渲染，否则它会选一个截图好看、在面板里难读的布局。

## 图上的状态

一条线索图谱的依赖图同时承载两样东西，而它们绝不能用同样的方式被编辑：

- **主干**——什么靠在什么上，手画的，因为计划是一种判断；以及
- **状态**——他们实际拿到了什么，派生的，因为它每次会话都在变，而手画的它会无声地过期。

有两条路线，而**SVG 那条是首选**——它是能塞进那一栏的那条，因此也是他们真会去看的那条。

**路线 1 —— 属性主干 → 生成的 SVG。线索图谱用这条。** 主干住在图谱的 `graph:` 属性里（`goal`、`foundations`、可选的 `nodes` 用于任何已计划但还没写出来的东西，以及 `edges`）。`Tools/vault-chart.mjs` 从它*加上概念笔记*渲染出 `Learn/Viz/<subject>-map.svg`，图谱用 `![[<subject>-map.svg]]` 嵌入它。概念节点在主干里不带文字：它们的框标签是概念自己的 `short:`，这样每条注解只有一份副本。任何东西移动之后就重新生成。

**路线 2 —— mermaid 主干 → 生成的 classDef。** 仍然支持，所以图谱可以一张一张地迁移。状态住在图里 `%% BEGIN generated · vault-map.mjs` 和 `%% END generated · vault-map.mjs` 这两个标记之间，由 `Tools/vault-map.mjs` 重写它。绝不要编辑那个块；重跑脚本。*课程计划*用的仍然是这条路线，那里的图只画一次、再不回看。

- 脚本读每张图谱的 `nodes:` 属性——`N1: 真菌穿过它的食物生长`，图节点 id → 概念笔记——并从那条笔记的 `status`、它的 `fragile` 标记和它的提取次数给节点上色。**绿色** established，**琥珀色** learning，**红色虚线** fragile，**灰色点线** planned。
- 一张图谱没列出的节点画成 `planned`：计划就是这样不再看起来像一份清单的。一个背后没有笔记的框不是教过的概念，而图不该暗示它有一个。
- **脚本依赖的两条标签约定：** 标签里含 🎯 的节点是目标，标签以 `Foundation` 或 `Held` 开头的节点是根基。两者都不上色，因为两者都不是他们学的东西。其他每个节点都是教学节点，拿到一个状态。
- `node Tools/vault-map.mjs` 做检查；`--write` 做更新。它**在会写出让 mermaid 噎住的图时以非零状态退出**——一条 `nodes:` 条目指名一个不存在的笔记是失败，把标签散文误当成节点 id 也是。

因为状态是派生的，图不可能和笔记不一致。这就是全部要点：它是这个库里唯一一张*视图*而不是制品的图。

## 给绘图员写简报

最常见的失败是**塞得太满**——每多一个标签都让图更难读，*也*更不可能正确。写简报之前，削减到承载这个想法的最少元素，并对每一个问：*如果我把这个删掉，想法还清楚吗？* 清楚，就删掉。

把想法**和**具体的元素都给绘图员——不要一个含糊的话题，也不要一长串检查项：

- 差：“画一张关于板块边界的图”
- 好：“```mermaid graph TD```。四个节点：`divergent`、`convergent`、`transform`，每个带一个短标签说明发生了什么（`new crust`、`crust destroyed`、`crust slides`）。把它们画成三个兄弟，不是一条链——它们是备选项，不是步骤。不要标题。要点是边界类型由相对运动来定义。”

要包含：媒介、元素、布局必须表达什么，以及什么可以丢掉。如果你的简报列了超过大约七个元素，发出去之前先砍。

**绘图员看不见自己的渲染。** 这是没有渲染工具链做这件事的唯一真实局限，而它意味着检查是你的责任：读它返回的块或文件，确认每条边和每个标签说的都是你的意思，并确认它小到能读。如果它错了，带着具体更正退回去——它写的那个文件就是将被嵌入的文件。

## 把它放好

绘图员写进 `Learn/Viz/`。然后：

- **mermaid**：把块粘进正在讲授这个想法的笔记（会话笔记或概念笔记），放在学习者需要它的位置。把图的源码留在笔记里——一张你以后能编辑的图，比一张图片更值钱。
- **SVG 或其他文件**：用 `![[filename.svg]]` 嵌入——一条双链嵌入按文件名在库里任何地方解析，所以名字必须唯一且描述性。内容密集时加一个显示宽度：`![[cladogram-arthropods.svg|600]]`。

用一句话把这张图介绍出来，说明该看什么，然后让它承载那个想法。不要在散文里把每个元素都叙述一遍——那会毁掉画它的目的。

## 让它们以后还有用

图是可复用的教学资产，它们会累积成某种真实的东西：一份属于他们各领域结构的个人地图集。两个习惯让这件事有回报：

- 按它们展示的东西命名文件，而不是按它们来自哪次会话（`kant-copernican-turn-dependency.svg`，不是 `viz-2026-02-14.png`）。
- 当一张图是一个概念最清楚的陈述时，从概念笔记本身链接它，让笔记有那张图，而不只有文字。

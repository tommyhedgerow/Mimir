# 这个库

这个库是讲授的记忆。对话不是。如果一次会话在磁盘上什么也没产出，它就什么也没留下——所以一次会话末尾的写回是讲授的一部分，不是事后补的。

## 会话惯例——在任何别的事之前先做这个

两条固定做法。它们不是装点：**学习者读的是库，不是聊天**，而库是图能渲染出来的地方。一次遵循了方法、却把笔记留到最后的会话，等于让学习者瞎着上课。

1. **一开始就创建会话笔记，并在 Obsidian 里打开它。** 一开始——在探测之前，不是讲授之后。带属性的骨架就够打开了；内容随着会话进行填进去。
   - 从 `Learn/Templates/Session.zh-CN.md` 创建 `Learn/Sessions/YYYY-MM-DD Short Topic.md`。
   - 从 shell 打开它：`open "obsidian://open?vault=<registered vault name>&file=<url-encoded vault-relative path>"`。文件名里的空格、破折号和其他非 ASCII 字符必须做百分号编码；用 `python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1]))' "Learn/Sessions/…"` 来构造这个 URI，不要手工编码。
   - 从 `~/Library/Application Support/obsidian/obsidian.json` 取已注册的库名——读它，不要猜。如果名字解析不了，`obsidian://open?path=<absolute path>` 是退路。
   - **会话文件名里不要有撇号。** 它们会让 URI 和每一条指向该笔记的 `[[双链]]` 都变复杂。
2. **笔记随着会话进行写，不要留到末尾。** 探测表、计划及其 mermaid 图、每个节点的四个动作都实时写进去，按它们发生的顺序。课程进行中他们就在旁边读，所以事后重建的笔记已经辜负了他们。
   - **诚实胜过整齐。** 如果计划从未被批准，如果会话提前停了，或者如果什么都没教，笔记就直白地说出来——复习队列也保持为空。空队列是一个真实状态；编造的条目不是。
   - 下面那次会话末尾的写回仍然完整进行。实时笔记是它的步骤之一，不是其余步骤的替代品。

## 这个库是什么，不是什么

它是**工坊**：会话、正在做的概念、图谱、复习队列、来源、图。这里的一切都可以是临时的、难看的、半成品、被重写的。

它不是**文库**。完成的、打磨过的笔记被发布进文库，那是学习者自己的长期知识库，装着他的其他笔记。除了下面那一步发布，什么都不写进文库，而这个库里的东西也不该假定文库的文件存在——两个库看不见彼此的 `[[双链]]`。

创建任何东西之前先用 `glob`/`grep`：**先搜，再写。** 一个已经有笔记的概念上再写第二条，比一条不完美的现有笔记更糟，因为图谱现在自相矛盾了。

## 属性（frontmatter）

每条笔记都带 YAML 属性（frontmatter）。键完全按下文保留——管理员、复习队列和发布步骤都读它们。

**会话笔记** —— `Learn/Sessions/YYYY-MM-DD Short Topic.md`：

```yaml
---
date: 2026-02-14
type: session
topic: 康德的哥白尼式转向
subjects: [philosophy]
tags: [learn, session]
status: done          # draft | in-progress | done
probe_checks: 12      # 探测问了多少道
probe_correct: 9      # 他们答对多少——低分是瞄得准的探测，不是糟糕的会话
teach_checks: 5       # 摆给他们的节点检查
teach_correct: 5
books: []             # 每次会话最多 2 本——镜像进 Learn/阅读清单.md
terms: []             # 这次会话用到的冷门词——每个在 Learn/Glossary/ 里一条笔记
published:            # 由发布步骤填入
---
```

计划的依赖图不再作为 mermaid 块写进正文：它是这条笔记属性里的 `graph:` 主干（`foundations`、`nodes`、`goal`/`goals`、`edges`），加上一张在计划所在位置生成的 `![[…-graph.svg]]`。一旦一个计划节点变成一个概念笔记，就把它加进顶层 `nodes:` 映射，并从 `graph.nodes` 里去掉——正是这一点让计划图按他们实际持有的东西给自己上色。运行 `node Tools/vault-map.mjs`（校验）和 `node Tools/vault-chart.mjs`（绘制）。

正文里别的都不是必需的——用会话模板（`Learn/Templates/Session.zh-CN.md`）拿形状：目标、探测表、已批准的依赖图、带动机推导的各节点、带 ✓/✗ 的检查表，以及来源。`Learn/Templates/` 里还有 `Concept.zh-CN.md` 和 `Map.zh-CN.md`。

**概念笔记** —— `Learn/Concepts/Concept name.md`。一个想法。标题尽可能平实地陈述这个想法。

```yaml
---
type: concept
subjects: [philosophy]
status: established   # seed | learning | established
short: 一行，印在线索图谱的依赖图上
depends_on: ["[[另一个概念]]"]
fragile: false        # true = 教过但不结实；在上面建东西之前先冷提取
taught: 2026-02-14
review_due: 2026-02-21
retrievals: []        # 每次复习一条，最早的在前
tags: [learn, concept]
---
```

`retrievals:` 是这里唯一记录**历史**而不是状态的字段，概览的提取日志读的就是它。每次复习追加一条，绝不重写：

```yaml
retrievals:
  - 2026-09-23 · held · next 2026-10-07
  - 2026-10-07 · partial · next 2026-10-21
```

中间那个词只用 `held`、`partial` 或 `missed`——复习队列自己的词汇——因为将来某张图表能数的就是这三个词。四次干净的提取就让这个概念 `established`。

正文：这个想法，用他们自己的语域写两三句；然后是**为什么它非得是这样**（那条带动机的推导——正是这一部分让笔记值得留存）；然后是**它靠什么成立**和**什么靠它成立**，写成双链；然后是**我在哪里弄错了**，如果他们错过；然后是**Sources**，带扩展链接，*以及同样的链接行内出现在散文里*（见下面的链接规则）。

## 链接——行内优先，清单其次

**这是一条长期规则，不是样式偏好。** 一个专有名词、运动、物种、事件、地点、王朝、作者或概念在一条笔记里第一次出现时，就带着一条指向它条目的行内链接——学习者读的是笔记，而在名字出现的地方就能跟过去的链接，比末尾的一份书目更值钱。

- **每一个专有名词、文本、王朝、人物、运动、物种、事件、地点或概念，在笔记正文里第一次出现时都拿到一条真正的 markdown 链接**——`[孔子](https://en.wikipedia.org/wiki/Confucius)`，不是光秃秃的文字。
- **Sources** 小节保留，作为收集起来的清单，每条配一行说明它好在哪。**它是行内链接之外的东西，绝不是它们的替代。** 只有一份 Sources 清单的笔记不合这条规则。
- 这条规则适用于会话笔记、概念笔记和图谱笔记——包括参考表、节点评述和检查表。如果一个名字出现在表格单元格里，就在那里链接一次。
- 不要凑数：只链接真正能扩展课程的东西，也绝不要把名字链接到错误的条目。行内链接不是给每个普通名词都加链接的借口。
- 它要紧的理由：**笔记是学习者阅读的地方，而一个在遇见名字的那一刻就能跟过去的链接，比末尾的一份书目更值钱。** 库是讲授的界面，不是讲授的记录。

**图谱笔记** —— `Learn/Maps/Subject — map.md`。一份内容图谱：这条线索的概念按依赖顺序排列，每个都是一条双链配一行注解，加上当前的前沿。

```yaml
---
type: map
subject: mycology
state: complete             # in-progress | paused | complete | index
opened: 2026-09-16
frontier: 一行——这条线索实际站在哪里
next: 一行——下一个节点
nodes:                      # 图节点 id → 概念笔记；没列出的一律是 `planned`
  N1: 真菌穿过它的食物生长
graph:                       # 主干：结构住在这里，不在图里面
  goal: 真菌是什么，它在外面做什么
  foundations:
    - F1 | 除了穿过表面，什么也吸收不了
  edges:
    - F1 -> N1
    - N1 -> G
tags: [learn, moc]
updated: 2026-09-16
---
```

`nodes:` 映射是连接图和概念笔记的东西，所以一个概念从 `learning` 变成 `established` 时，没有哪张图谱需要被手工碰一下。`graph:` 块是声明形式的主干；`Tools/vault-chart.mjs` 从它和从笔记画出 `Learn/Viz/<subject>-map.svg`，图谱笔记用 `![[<subject>-map.svg]]` 嵌入那个文件。**概念节点在主干里不需要任何文字**——它的框标签就是概念自己的 `short:`，所以每条注解都恰好只有一份副本。`frontier:` 是概览显示的一行版本；它下面那个散文写的 *Frontier* 小节承载细节。

在任何创建或改动概念的会话之后运行 `node Tools/vault-map.mjs`；它校验主干（一条边指名一个不存在的节点是失败，不是警告）并报告任何漂移的东西。然后 `node Tools/vault-chart.mjs` 重绘。一张图谱也可以把主干放在一个 ```mermaid 块里，那是较老的机制就地着色——支持，但不再是新图谱该做的事。

**来源笔记** —— `Learn/Sources/Author Year — Title.md`：它是什么、它好在哪、它给哪些概念打底，以及任何留存的研究简报。

**复习条目** —— `Learn/Reviews/复习队列.md` 里的一行 `- [ ]`。

## 状态是承重的

- `seed`——写下来了，还没被理解。绝不假装不是这样。
- `learning`——教过了，至少检查过一次，仍然不稳固。
- `established`——检查过两次，隔一段时间后仍能挺过提取。
- `fragile: true`——**不是状态而是一个标记，而且它在图谱上压过状态。** 教过但不结实：在上面建任何东西之前先冷提取它。真菌学图谱里的半径/直径相除就是模式标本——探测时错了两次，讲授中修好一次。
- 会话上的 `status: draft` 意味着它还没完成；`done` 意味着写回已完成，可以发布。

绝不要因为某样东西被解释过就把它标成 `established`。它是在他们冷着提取出来时才算确立的。

## 术语表——这个库的词汇

`Learn/Glossary/` 存着**每个冷门术语一条笔记**（`type: term`），而 `Learn/术语表.md` 是把它们作为一张可筛选表格嵌入进来的枢纽。一条术语笔记很小：

```yaml
---
type: term
term: Serotiny
subjects: [life sciences]
field: Plants & ecology     # 平实语言的领域，供枢纽分组用
niche: true
taught: 2                   # 0–3：讲授实际触及了这个概念多少
tags: [learn, glossary]
updated: 2026-09-16
---
```

正文：定义（一到两句，**第一次出现处带行内维基百科链接**），然后是*它为什么在这里*——它来自哪次会话和哪条线索——然后是*教过*。

**门槛很高，而规则是单向的。** 一个词在一次会话*用到了它、并且为了课程能往下走不得不定义它*时，才有资格立条目——普通读者本来就拥有的词（干旱、养分、森林、岩石）永远不立，也不会为还没教过的材料先写条目。所以术语表不可能跑到他们前面：每一条目都追溯到一节课。当一次会话更正了一个术语的含义时，术语条目**在同一轮里**被更正——`Serotiny` 就是模式标本，库里必须把 *serotiny*（任何刺激）与 *pyriscence*（火）保持区分，因为把它们当同义词教曾被记录为一次错误。

在下面写回的第 2b 步里贡献，而领域名是承重的：`Glossary.base` 按 `file.inFolder("Learn/Glossary")` 筛选并按 `field` 分组，所以一个没有 `field` 的术语会从枢纽的分组里掉出去。

## 阅读清单

`Learn/阅读清单.md` 是书累积起来的唯一地方，按线索分组。他们定下的规则：**每次会话至多一两本书**，在会话末尾选，选那些能延伸这次会话所不能及的——一本合适的胜过两本凑数的。绝不在讲授期间，绝不是书目倾倒。

每个条目给出**书名、作者、年份、一条链接，以及一行说明为什么**。链接规则，用他们的话说：**有精装零售链接的地方就用它；没有就用 Goodreads。** 书上清单之前要核实书是真的——作者、书名、年份——会话笔记和清单都不带任何出处未经核实的书名。

会话笔记镜像它贡献的东西：属性里的 `books:` 清单（每条一个 `"Title — Author (year)"` 字符串）和一个承载同一条推荐及其理由的 `## 📚 阅读` 小节。`Dashboard.base` 有一个读 `books` 的 **Books** 视图。体裁规则是他们定的，而且说得明确：**只限已出版的虚构与非虚构书籍——不要学术论文，不要期刊文章。**

## 会话末尾的写回

按顺序：

1. **会话笔记**，从模板来，检查表诚实地填好——包括那些失手。
2. **概念笔记**，只为可持久复用的想法写。每个会被复用的想法一条。从会话笔记里、以及从它依赖的每个概念里链接过去。
2b. **术语表条目**——会话用过、并且不得不定义的每个*冷门*词一条笔记，外加会话 `terms:` 清单里的一条。会话改变了含义的任何现有术语，都要在同一轮里更正。门槛和格式见上面*术语表*。
2c. **阅读清单**——至多两本书，追加到 `Learn/阅读清单.md` 里正确的线索下面，带书名、作者、年份、链接和一行说明为什么，并镜像进会话的 `books:` 清单和它的 `## 📚 阅读` 小节。先核实每本书是真的。什么都没教的会话不拿书。
3. **该线索的图谱**：加上新概念，移动前沿，并在图谱的 `nodes:` 块里声明每一个。然后运行 `node Tools/vault-map.mjs --write`，让图的状态和笔记一致。图是生成的，不是手画的。
4. **`学习者档案.md`**：已确认的下限（他们答对并从此拥有的东西）、找到的上限（它在哪里耗尽）、发现的错误认知以及它们是否被撬掉，还有随着它们变得可见的偏好（想要更多苏格拉底式、不喜欢长开场白、喜欢早点看到一张图，等等）。
5. **`学习清单.md`**：勾掉已完成的，加上这次会话显露为新兴趣的东西，并记下这次会话让什么变得明显是下一步需要的。
6. **`复习队列.md`**：教过的每个概念一条，带它第一次到期的日期——而且**在一次复习会话上，重排它的期之前先把结果追加到概念笔记的 `retrievals:` 里。** 队列那一行是承诺；`retrievals:` 是承诺被履行的唯一记录，也是概览读的东西。只写在散文里的结果，是以后什么都数不了的结果。
7. **`Learn/../🌱 学习索引.md`**：把会话加进最近列表，把新图谱加进图谱列表。
8. 可选但值得：在他们自己的库里当天的日记笔记里写一行指向这次会话——只在他们记日记并且要求了的时候。

真正有归档工作要做时，`subagent_librarian` 调用是完成第 2、3、6、7 步的正确方式；会话笔记和档案你自己写，因为它们承载你对这次会话的判断。

## 复习队列

`Learn/Reviews/复习队列.md` 是一份朴素的清单，最新的在前：

```markdown
- [ ] [[概念]] — 到期 2026-02-21 — 问：重建推导，不是背定义
- [x] [[概念]] — 复习于 2026-02-28 — held，下次 2026-03-14
```

间隔：第一次复习在一周内，之后每次干净提取就把间隔翻倍；失手时减半，并在重新排期之前修复概念笔记。一次复习会话是它自己那一类会话——怎样进行见 `reviewing` 技能。队列是一份承诺：一条再也不会到期的条目，就是一个被悄悄丢掉的概念。

## 发布到文库

当一次会话是 `status: done`、它的概念笔记也 `established` 时，它可以被发布进文库：

- **从 Obsidian：一次点击。** 活动笔记的发布按钮/命令把它和它嵌入的一切都复制进文库里的镜像路径：`Learn/Sessions/x.md` → `Library/Learn/Sessions/x.md`，`Concepts/`、`Maps/`、`Viz/`、`Sources/` 同理。它在源笔记里盖上 `published:`，这样发布状态在这里看得见。
- **从这里：** 运行 `Tools/publish-to-library.sh <path-relative-to-vault>`（加 `--with-links` 把它的链接概念笔记一起带上）。

发布之前，检查笔记能独立站住：文库解析不了一条指向只住在这个库里的笔记的 `[[双链]]`。要么把那条链接承载的内容写进正文，要么把它转成指明该概念的纯文本。维基百科和其他外部链接没问题，而且是被想要的。不要发布草稿，不要发布仍然含有你知道是错的主张的笔记，也绝不在没问过的情况下覆盖学习者在文库里的自己的笔记。

## 自主权——那条固定的边界

在 `Learn/`、`Tools/` 和 `Inbox/` 里面：自由创建、编辑和重组，包括移动一条笔记并修正指向它的双链。

在它们外面——这个库里任何别的东西，以及文库或磁盘上任何地方：**只读，除非他们要求。** 提出确切的改动然后等。绝不删除他们的文字，绝不重命名他们的文件，绝不“整理”文库。

两个习惯让这件事安全：编辑一个文件之前先读它，以及任何移动之后 grep 旧名字并修好那些链接。

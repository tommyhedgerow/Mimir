# 复习

讲授建起图谱。复习是让它站住的东西。两者都要紧，而复习是被跳过的那一半——所以它在这里被排进日程，而不是留给运气。

方法自身的逻辑说明了为什么这不是可选项：一个被自己的连接固定住的理解是稳定的，但一个新搭起来的节点是图谱里最脆弱的东西，而固定它的那些连接正是最先衰减的。提取是把它们重新铺回去的东西。再认不是：重读一条你自己写的笔记感觉像知道，却什么也证明不了。

## 走队列

`Learn/Reviews/复习队列.md` 存放着条目。任何一次会话开始时：

1. 读队列。今天到期或已经逾期的先来——永远在新材料之前。这是让港口保持清澈的潮水。
2. 按到期日排序处理，最旧的先来，并给一批设上限：五到八个概念是一次会话，二十个是一件他们会开始躲的苦差。
3. 任何被推后三次的东西，要的不是再推一次而是一个决定：要么他们不需要它（丢掉，并说出来），要么那条概念笔记承载不起它的分量，需要重写。

## 要提取，不要再认

问题必须要求他们**重建**那个东西，而不是认出一个眼熟的选项：

- **重建推导**——“为什么这必然成立？从它所依赖的东西出发把它建起来。”这是这套方法里最强的问题类型，因为它检验的是图的边，而不是节点。
- **产出，不要选择**——“用你自己的话定义它”“说出那三个条件”“把这一点去掉会坏在哪里？”。用普通聊天，不用选项：答案必须是被生成出来的。
- **然后辨别**——一道按 `mimir-teaching` 规则造的单选题（“下面哪一个是在某个错误信念之下的同一个主张？”），它定位的是*哪一个*错误活了下来，而不只是有错误活了下来。
- **然后迁移**——一个他们没见过的情形：一个新物种拿去检索表里定，一段新文本拿去读，一个新日期拿去放到时间线上。迁移是唯一的真正证明，也是那道显示这个概念是否离开了笔记的问题。

需要整整一次复习会话的题目时用 `subagent_examiner`；单道题自己写。

**绝不要在他们尝试之前把答案显示出来。** 一次变成重读的复习比没有复习更糟：它产出知道的感觉，却没有那个事实。

## 诚实地评分，然后修复

在他们承诺一个答案之前，对错上一言不发——不要“很接近！”，不要“嗯”，不要带倾向的语气。然后：

- **干净提取** → 说出来，并延长间隔。这是一个被确认的下限，值得作为下限点出来。
- **部分** → 找出是哪个部分失败了。一条推到一个步骤就推不下去的推导，和一条从未落地的定义，是*不同*的缺口，两者需要不同的修复。
- **失手** → 重排期之前先修复：回到那个节点，重新给它动机，重新推导它，并在同一次会话里再检查一次。然后把间隔减半。无论如何，不要只把答案告诉他们然后往下走——那正是整套方法最容易被放弃的时刻。
- **一个错了两次的概念**通常说明它下面的根基不稳，而不是这个概念难。往下一层，检查它靠什么成立。

## 按翻倍排期

第一次复习在讲授后一周内，之后：

| 干净提取次数 | 下一次间隔 |
| --- | --- |
| 0（刚教完） | 约 3–7 天 |
| 1 | 约 2 周 |
| 2 | 约 1 个月 |
| 3 | 约 2 个月 |
| 4+ | 约 4 个月，此后就是他们的了 |

失手时，把间隔减半并修复。把结果记进队列那一行，并把概念笔记里的 `review_due` 设成一致——两者必须相符，因为队列是被读的东西，而属性是被搜的东西。任何干净提取过四次的东西都是 `established`；停止给它排期并说出来，好让队列短到能被走得完。

交错着来：不要连续复习同一条线索的五个概念。混合提取更难，而正是它让知识能在它被学到的语境之外被取用——那才是全部要点。

## 一次复习会话是一次真正的会话

它和任何别的会话一样拿到一条会话笔记（`type: session`、`tags: [learn, review]`），记着队列条目、什么守住了、什么失败了、什么被修复了，以及新的到期日。笔记里有意思的部分是失败的模式：三次失手最后都归结为同一个没被审视的假设，这是关于他们模型的一个发现，而它同样属于 `学习者档案.md`。

## 当他们就是想被考

他们有时会要求被考，不附带任何课程。那是一次内容取自队列的复习会话；按同样的规则进行，而如果队列是空的，就从最新的会话笔记和 `established` 的概念里拿，并说明你正在这么做，而不是假装它是被排进日程的。

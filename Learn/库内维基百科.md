# 库内维基百科

> Wikipedia 集成实际能做到什么，对着原始来源核实于 **2026-09-17**。短版本：**悬停预览和搜索能用，而从 Obsidian 内部把文章存进 Wikipedia 阅读列表对任何人都做不到** —— 不是没有插件作者写过，而是 Wikipedia 不提供这个 API。这份笔记的其余部分是什么该装、以及为什么。

## 什么是可能的，什么经得起核实

| 想要的 | 结论 |
| --- | --- |
| 悬停预览一个链接的文章 | **可以** —— `Hoverlay`。核心的*页面预览*插件完全做不到。 |
| 从库内搜索 Wikipedia | **可以** —— `Wikipedia Helper`。可以插入链接，或者为每篇文章创建一条笔记。 |
| 从库内把文章存进 Wikipedia 列表 | **做不到，对任何人都做不到。** 不存在这样的 Obsidian 插件，而且 Wikimedia 没有为此公开任何 API。变通办法见下。 |

## 悬停预览

**Obsidian 内置的页面预览对外部链接不起作用。** 它自己的文档说它「让你在把光标悬停在**内部链接**上时预览一个页面」（[obsidian-help, Page preview](https://github.com/obsidianmd/obsidian-help/blob/master/en/Plugins/Page%20preview.md)）。这个库里的每一个 Wikipedia 链接都是外部 markdown 链接，所以核心插件对它们全都看不见。这就是需要第三方插件的全部原因。

**装 `Hoverlay`** —— id `hoverlay`，版本 0.4.1，发布于 2026-08-01，作者 zspatter。它在 Obsidian 的官方注册表里（[community.obsidian.md/plugins/hoverlay](https://community.obsidian.md/plugins/hoverlay)），所以可以从应用内的浏览器安装：*设置 → 第三方插件 → 浏览 → 搜索 “Hoverlay”*。它把链接预览成一个实时页面、一个阅读模式视图，或者一张元数据卡片，而它自己的 README 专门点出了 Wikipedia 这种情况——Wikipedia 会发 `X-Frame-Options` 头，这就是更早那些基于 iframe 的预览插件在它上面失败的原因。不需要 API key，不经过第三方预览服务；页面被取进一个沙箱化的 webview，然后丢弃。

*一个要说明而不是埋起来的提醒：*注册表注明它「尚未经过 Obsidian 官方人工审核」。对于一个在 webview 里渲染页面的库，装之前这一点值得知道。它碰到的一切都是你已经链过去的网页。

**那一个 Wikipedia 专用选项，以及为什么不推荐它。** [szvest/obsidian-wikipedia-link-preview](https://github.com/szvest/obsidian-wikipedia-link-preview) 是真实存在的——id `wikipedia-link-preview`，v1.0.0——但它有三个取消资格的毛病：它的最后一次发布是 **2024-08-14**，它**只**对 `https://en.wikipedia.org/wiki/...` 链接触发，而且它**根本不在 Obsidian 的注册表里**（已核实：`community-plugins.json` 和统计文件里都没有），所以尽管它的 README 说可以从应用里装，其实装不了。它需要手动装文件，而它两年前的发布是一个兼容性风险。

如果 Hoverlay 让人失望，注册表里还有：`url-preview`（“URL Preview”，0.8.0，2026-09-08）和 `link-preview`（“Link Preview”，0.1.4，2025-01-28）。两个都未经审核；两个都不是 Wikipedia 专用的。

## 从库里搜索 Wikipedia

**装 `Wikipedia Helper`** —— 插件 id 是 `wikipedia-search`，这就是那个坑：显示名改过，而**为了向后兼容刻意保留了 id**。id `wikipedia-search`，显示名 “Wikipedia Helper”，作者 StrangeGirlMurph，版本 2.7.3（2026-08-01），支持移动端。应用内浏览器：搜索 “Wikipedia Helper”。一个项目一个仓库（[obsidian-wikipedia-helper](https://github.com/StrangeGirlMurph/obsidian-wikipedia-helper)）——不是 fork。文档：[wikipedia-helper.murphy.science](https://wikipedia-helper.murphy.science/commands.html)。

它在这里要紧的本事：搜索每一个 Wikimedia 项目和每一种语言（`nl: 词` 这样的前缀指定语言），**在光标处插入链接**，给选中的文本加超链接，**从模板为一篇文章创建一条笔记**，以及把一篇文章直接打开进一个 **Web viewer** 标签。最后那条命令是下面那个变通办法的承重墙。

*避开*旧的 `obsidian-wikipedia` 插件（2021，无人维护）——Wikipedia Helper 取代了它。

## 存进 Wikipedia 列表——诚实的答案

**没有 Obsidian 插件做这件事，也没有插件做得到。** 社区注册表里全部 7,729 条都按 reading-list、watchlist 和 saved-page 这些词搜过；唯一的命中是不相关的稍后读应用（Pocket、Instapaper）。更有决定性的是，**Wikipedia 自己也不提供这个能力**：

- Wikipedia 的 **Reading Lists** 在 **2026 年 9 月 14 日**上线网页端（其他所有 wiki 是 9 月 28 日）。文章页上的一个书签图标把它加进一个私有列表，一个扁平列表，上限 5,000（[MediaWiki: Reading lists](https://www.mediawiki.org/wiki/Readers/Reader_Experience/Reading_lists)）。
- 后端是 **ReadingLists** 扩展，它在英文 Wikipedia 上是活的——但它的写接口被文档描述为*「内部的或不稳定的……你不应该使用它」*，需要交互式登录和 CSRF token，而且**没有公开的 OAuth**。所以任何外部应用都没有受支持的办法往你的列表里加东西，无论有没有人写插件。
- **监视列表和阅读列表是两回事** —— 存一篇文章不等于监视它，监视也不等于存它。监视列表可以通过已认证的 MediaWiki API 编辑，而同样没有任何 Obsidian 插件暴露它。

**变通办法，两下点击而不是一下。** Wikipedia Helper 的 *Open Article* 命令把文章放进一个 Obsidian 的 **Web viewer** 标签；那个页面里的书签图标把它加进列表。文章是在 Obsidian 里读的，也是从 Obsidian 内部存下的——只是不是由一条库内命令完成。Obsidian 自己的 URI scheme 打不开任意的外部网址，所以这里没有可以自动化的捷径。

## 改成把整篇文章剪下来

对于值得留存而不是加书签的材料，官方的 **Obsidian Web Clipper**（[obsidian.md/clipper](https://obsidian.md/clipper)）在它的官方模板仓库里有一个 Wikipedia 专用模板——[`wikipedia-clipper.json`](https://github.com/kepano/clipper-templates/blob/main/templates/wikipedia-clipper.json)。它对任何 `*.wikipedia.org/wiki/...` 网址触发，把 `#mw-content-text` 剪成 markdown，带上标题、来源、作者、描述和标签。这样一篇文章会作为一条笔记落进这个库，对会话真正用到的任何东西来说，这是和阅读列表不同、而且往往更好的答案。它碰不到 Wikipedia 那个列表；它剪进笔记库。

## 安装清单

下面两个插件就是能用的那套配置。**这个库两个都没预装** —— 从 Obsidian 的注册表安装（*设置 → 第三方插件 → 浏览*），然后**重载 Obsidian**（或者重新打开库），它们才会加载：一个靠改配置启用的插件在应用重启之前并没有在运行。核心的 **Web viewer** 插件也要打开，因为它支撑着 Wikipedia Helper 的 *Open Article* 命令，而那个保存的变通办法依赖它。

| 插件 | Id | 状态 | 为什么 |
| --- | --- | --- | --- |
| Hoverlay | `hoverlay` | 从注册表安装 | 悬停预览，核心的页面预览对外部链接做不到 |
| Wikipedia Helper | `wikipedia-search` | 从注册表安装 | 搜索、插入链接、文章转笔记、在 Web viewer 里打开 |
| Web Clipper（浏览器扩展） | n/a | 未安装——浏览器那一侧 | 把整篇文章剪进这个库，带一个 Wikipedia 模板 |

**不推荐，以及为什么：** `wikipedia-link-preview`（不在注册表里、2024 年、仅英文）、`obsidian-wikipedia`（2021 年起就死了）。

### 跑起来之后先试这几件事

- **在会话笔记里悬停任意一个 Wikipedia 链接** —— 预览应该在一个浮动窗口里打开。如果什么也没发生，插件还没加载；检查*设置 → 第三方插件*里两个都显示为已启用。
- **命令面板 → Wikipedia Helper。** 搜索任意文章，然后在光标处插入一个链接，或者为它在库里创建一条笔记。
- **保存的工作流：** *Open Article* 把页面放进一个 Web viewer 标签，那个页面里的书签图标把它加进 Wikipedia 阅读列表——就是上面那一节里的两下点击路径。
